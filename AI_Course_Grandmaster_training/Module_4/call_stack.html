JavaScript Call Stack

1. LIFO — Last In, First Out

Code: 
// Simple demo of push / pop order
const stack = [];

stack.push("first()");
stack.push("second()");
stack.push("third()");

console.log("on the stack:", stack);

console.log("popped:", stack.pop());  // third()
console.log("popped:", stack.pop());  // second()
console.log("popped:", stack.pop());  // first()

// The last one in is the first one out.

2. Frames — Order of Calls and Returns

Code: 
function first() {
  console.log("first: start");
  second();                    // pushes second()
  console.log("first: end");
}

  console.log("second: start");
  third();                     // pushes third()
  console.log("second: end");

  console.log("third: running");

4. Stack Trace

Code: 
function outer() { middle(); }
function middle() { inner(); }
function inner() { throw new Error("boom"); }

try {
  outer();
} catch (err) {
  console.log("Message:", err.message);
  console.log("--- stack trace ---");
  console.log(err.stack);
}

// The trace shows the frame order:
//   inner  ← crash site
//   middle ← its caller
//   outer  ← its caller
// This is how you find where an error came from.

5. Stack Overflow

Code: 
// No base case → every call pushes a new frame
function recurse(n) {
  return recurse(n + 1);
}

try {
  recurse(0);
} catch (err) {
  console.log("Caught:", err.name);
  console.log("Message:", err.message);
}

// Each call adds a frame.
// When the limit is reached the engine throws:
//   RangeError: Maximum call stack size exceeded

// ---- Correct version with a base case ----
function countdown(n) {
  if (n === 0) return "done";       // base case stops the stack
  return countdown(n - 1);
}
console.log(countdown(5));

6. Recursion Traced — factorial(4)

Code: 
function factorial(n) {
  console.log("push factorial(" + n + ")");
  if (n <= 1) {
    console.log("pop  factorial(1) = 1");
    return 1;
  }
  const result = n * factorial(n - 1);
  console.log("pop  factorial(" + n + ") = " + result);
  return result;
}

console.log("result:", factorial(4));

// Stack grows: 4 → 3 → 2 → 1
// Then unwinds: 1 → 2 → 3 → 4
// The multiplication happens on the way DOWN the stack.

7. Recursion vs Iteration

Code: 
// RECURSION — one frame per call
function sumR(n) {
  if (n === 0) return 0;
  return n + sumR(n - 1);
}

// ITERATION — one frame total
function sumI(n) {
  let total = 0;
  for (let i = 1; i <= n; i++) total += i;
  return total;
}

console.log(sumR(100));
console.log(sumI(100));

// Both give 5050.
// sumR uses 101 frames, sumI uses 1.
// sumR(100000) → RangeError
// sumI(100000) → works fine.

8. Blocking — One Stack, One Thread

Code: 
// This loop freezes the page for its duration.
// Nothing else can run while the stack is busy.
function block(ms) {
  const end = Date.now() + ms;
  while (Date.now() < end) { /* spin */ }
}

console.log("1. before block");
block(1500);
console.log("2. after block");

// Because JS has ONE call stack, timers, clicks,
// and rendering must wait until the stack is empty.

// The safe alternative:
setTimeout(() => {
  console.log("3. runs later on a fresh stack");
}, 0);

9. Async — Callbacks Start on a Fresh Stack

Code: 
console.log("A: sync start");

setTimeout(() => {
  console.log("C: timeout callback (new empty stack)");
}, 0);

Promise.resolve().then(() => {
  console.log("B: promise callback (after stack clears)");
});

console.log("D: sync end");

// Order matters:
// 1. Sync code runs first: A, D
// 2. Microtasks (promises) run next: B
// 3. Macrotasks (setTimeout) run last: C

// The call stack DOES NOT grow across async calls —
// each callback starts with an empty stack.

10. Quick Reference

Concept Meaning
Call stack Data structure that tracks which function is running
LIFO Last function called is the first to finish
Frame One entry on the stack: name, locals, params, return position
Push Happens when a function is called
Pop Happens when a function returns
Stack trace List of frames at the moment of an error
RangeError Thrown when the stack overflows
Base case The condition that stops a recursive function
Recursion One frame per call — can overflow on deep input
Iteration One frame total — safer for large loops
Blocking Stack is busy → page cannot respond
Async Callbacks run later, each on a fresh empty stack
Single-threaded Only one stack exists — one thing at a time
