Carousel and Horizontal Scrollspy

A slideshow component, and a nav that follows you down the page.

Time: 75-90 minutes Level: Intermediate Mode: Individual work

Learning Objectives

Carousel

  1. Write the required carousel structure — wrapper, inner, items, one .active item.
  2. Add previous/next controls and slide indicators with the correct data attributes.
  3. Add captions and use the fade transition.
  4. Control autoplay timing, pause behaviour and looping with data attributes.
  5. Drive a carousel from JavaScript using to, prev, next, pause, cycle.
  6. Explain the accessibility limits of a carousel.

Horizontal Scrollspy

  1. Explain what scrollspy does and when to use it.
  2. Build a horizontal navbar or pill nav that tracks the page scroll position.
  3. Set up scrollspy inside a nested scrollable container.
  4. Use rootMargin so a fixed header does not hide the active section.
  5. Use a list-group as a scrollspy target.
  6. Explain the Bootstrap 4 to 5 migration changes.

1. The minimal carousel

Four levels deep: wrapper, inner, items, and one active item. With data-bs-ride it plays on its own.

div#minCarousel.carousel.slide[data-bs-ride="carousel"] > .carousel-inner

<div id="minCarousel" class="carousel slide" data-bs-ride="carousel"> <div class="carousel-inner"> <div class="carousel-item active"> Slide 1 </div> <div class="carousel-item"> Slide 2 </div> <div class="carousel-item"> Slide 3 </div> </div> </div>
Two pieces to notice. The first item needs .active — forget it and you see a blank box. And data-bs-ride="carousel" is what starts the autoplay. Without that attribute the carousel sits still until something triggers it.

2. Previous and next controls

The arrows use data-bs-target to find the carousel. That value must match the wrapper's id exactly.

.carousel-control-prev / .carousel-control-next with data-bs-target and data-bs-slide
Slide 1
Slide 2
Slide 3
<button class="carousel-control-prev" type="button" data-bs-target="#ctrlCarousel" data-bs-slide="prev"> <span class="carousel-control-prev-icon" aria-hidden="true"></span> <span class="visually-hidden">Previous</span> </button> <button class="carousel-control-next" type="button" data-bs-target="#ctrlCarousel" data-bs-slide="next"> <span class="carousel-control-next-icon" aria-hidden="true"></span> <span class="visually-hidden">Next</span> </button>
The single most common carousel bug: data-bs-target="#ctrlCarousel" does not match the wrapper's id="ctrlCarousel". If the two strings differ by even one character, the arrow silently does nothing.

3. Indicators (the dots)

The dots use a data-bs-slide-to attribute with a zero-based index.

Three rules for indicators.
  • The index starts at 0, not 1. The first dot is data-bs-slide-to="0".
  • The first dot needs class="active" and aria-current="true".
  • Every dot needs its own aria-label for screen readers.

Attribute What it does Default
data-bs-ride="carousel" Start autoplay on load off
data-bs-interval="3000" Delay per slide in milliseconds 5000
data-bs-wrap="false" Stop at the last slide true (loops)

Accessibility warning. Setting data-bs-pause="false" means the carousel will keep moving even when a user tries to read or focus on a slide. For any carousel with text, leave the default hover pause in place, or provide a visible play/pause button.

7. Controlling the carousel from JavaScript

External buttons can drive a carousel with the bootstrap.Carousel API.

bootstrap.Carousel.getOrCreateInstance(el).prev() / .next() / .to(n) / .pause() / .cycle()
Index 0
Index 1
Index 2
var el = document.getElementById('jsCarousel'); var inst = bootstrap.Carousel.getOrCreateInstance(el); inst.prev(); // previous slide inst.next(); // next slide inst.to(2); // jump to index 2 inst.pause(); // stop autoplay inst.cycle(); // restart autoplay
Why getOrCreateInstance and not new bootstrap.Carousel(el)? Because the carousel already exists if it has data-bs-ride. Creating a second instance would attach a duplicate set of event listeners and cause double transitions. getOrCreateInstance reuses the existing one.

8. What Bootstrap does automatically for accessibility

Inspect the markup after the carousel starts playing and you will see Bootstrap adding attributes.

Attribute Added to Why
aria-hidden="true" Every inactive slide Screen readers skip slides that are not visible.
inert Every inactive slide Keyboard focus is blocked inside offscreen slides.
nothing Active slide The attributes are removed so it becomes available again.
What this means in practice. A link inside slide 3 is not reachable by keyboard or screen reader until slide 3 becomes active. That is why the Bootstrap team recommends keeping carousel content short and non-essential, and why autoplaying carousels with critical text are best avoided.

Add an aria-label to the wrapper so the whole region has a name:
<div id="heroCarousel" class="carousel slide" aria-label="Featured products">

Horizontal Scrollspy

9. A basic horizontal scrollspy

Scroll inside the box below and watch the pill nav at the top of the box update. This is the core pattern.

Nested scroller: data-bs-spy="scroll" + position: relative + height + overflow-y + tabindex="0"
Introduction Setup Usage FAQ

Introduction

This panel is a nested scroll container. It has a fixed height and overflow-y: auto, so its content scrolls inside the box instead of scrolling the whole page. Scrollspy watches this box.

Watch the pill nav above. As each section comes into view, Bootstrap moves the .active class to the matching link.

Setup

Three things make this work. The scroll container has data-bs-spy="scroll" and tabindex="0". It also has position: relative, a fixed height and overflow-y: auto in its CSS.

The nav has an id, and every link inside it points at a section id with a hash. The data-bs-target on the scroller matches the nav's id.

Usage

Use scrollspy on long documentation pages, changelogs, terms of service, API references, and any single-page layout with several clearly separated sections.

Do not use it when sections are short or when the nav is very long. The user will see the active pill jumping around faster than they can read.

FAQ

What if nothing highlights? In almost every case one of the four requirements is missing: no position: relative, no tabindex="0", a section without an id, or a data-bs-target that does not match the nav's id.

Does it work with a navbar instead of pills? Yes. Scrollspy finds any element with an href inside the target nav. Pills, tabs, navbars and list groups all work.

10. Horizontal navbar scrollspy

The same pattern with a full navbar. This is the shape used on most documentation sites.

navbar with .nav-link inside + a sticky nav bar at the top of the scroller
  • Overview
  • Install
  • Config
  • Deploy

Overview

The navbar is position: sticky inside the scroll container. It stays at the top of the visible area while the section content scrolls behind it.

Install

Because the navbar is sticky and covers the top of the container, a section title can be hidden underneath it. The data-bs-root-margin="0px 0px -70%" attribute moves the active boundary up so it fires before the title disappears.

Configuration

Every link inside the target nav needs an href that matches a section id with a hash. Links that do not match any section are simply ignored.

Deploy

With smooth scroll enabled, clicking a nav link scrolls smoothly instead of jumping. Bootstrap handles the animation; no custom JavaScript is needed.

Why -70% here? The root margin decides where the "active" trigger sits vertically. A larger negative value pushes the trigger higher up, which is what you want when a sticky or fixed header is covering the top of the area.

11. Vertical sidebar scrollspy (for contrast)

The markup is the same. The only difference is that the nav is stacked vertically instead of arranged in a row.

Same data attributes — only the visual column changes
Getting started Components Utilities Migration

Getting started

Scroll this panel and the sidebar on the left updates. The structure of the markup is identical to the horizontal case.

Components

Same data-bs-spy, same data-bs-target, same tabindex="0" on the scroller.

Utilities

The nav uses nav flex-column instead of a row. That is the entire difference between the vertical and horizontal versions.

Migration

Choose whichever shape fits the page. Horizontal fits a wide layout with a top header. Vertical fits a documentation layout with a persistent left column.

Choose based on layout, not on behaviour. Scrollspy does not care whether the nav is horizontal or vertical. It only cares that every link has an href that matches a section id.

13. Common mistakes

Mistake Symptom Fix
position: relative missing from the scroller Nothing highlights, or it fires at wrong offsets Add position: relative to the scroll container
tabindex="0" missing Keyboard users cannot scroll the region Add tabindex="0" to the scroller
Section has no id That section never activates Give every tracked section a unique id
data-bs-target does not match the nav's id Nothing ever highlights Make the two strings identical, including the #
Link href uses #sectionId but the section uses a different case That link never activates Match case exactly — HTML ids are case sensitive
Nested container has no height or overflow The container just grows; there is nothing to scroll Add a fixed height and overflow-y: auto
Fixed header hides the section title Active state fires too late Add data-bs-root-margin="0px 0px -40%"
Scrollspy element is the nav, not the scroller Nothing works data-bs-spy goes on the SCROLLING element, data-bs-target points at the NAV
Remember the direction. data-bs-spy="scroll" sits on the element that scrolls. data-bs-target="#navId" points at the element that receives the .active class. They are two different elements and it is easy to swap them by accident.

Snippet A — a carousel with a link in slide 2

Snippet B — a scrollspy

<nav id="docNav"> <a href="#intro">Intro</a> <a href="#setup">Setup</a> </nav> <div data-bs-spy="scroll" data-bs-target="#docNav" data-bs-smooth-scroll="true" style="position: relative; height: 300px; overflow-y: auto;"> <h4 id="intro">Intro</h4> <h4 id="setup">Setup</h4> </div>

Your analysis and fixes:

Show solution

Snippet A

  • Problem: the link See our pricing is inside slide 2. Bootstrap adds aria-hidden="true" and inert to inactive slides, so this link is invisible to screen readers and unreachable by keyboard until slide 2 becomes active. A user who cannot see the page will never know the link exists.
  • Fix options: move the link outside the carousel, or add a play/pause control and captions that make the carousel navigable, or replace the carousel with a static layout if the link is important. At minimum, add an aria-label to the wrapper so the region is announced.
<div id="heroC" class="carousel slide" data-bs-ride="carousel" aria-label="Featured content"> ... </div> <!-- And move the pricing link OUT of the carousel so it is always reachable by keyboard and screen reader users. --> <p><a href="/pricing">See our pricing</a></p>

Snippet B

  • Problem: the scroll container is missing tabindex="0". Keyboard users cannot focus the panel to scroll it with the arrow keys. When a scrollable region is not focusable, keyboard users are effectively stuck — they cannot read past the visible content.
  • Also worth noting: the nav has no aria-label. Screen reader users have no way to tell this navigation apart from the site's main nav in a landmark list.
<nav id="docNav" aria-label="On this page"> <a href="#intro">Intro</a> <a href="#setup">Setup</a> </nav> <div data-bs-spy="scroll" data-bs-target="#docNav" data-bs-smooth-scroll="true" tabindex="0" style="position: relative; height: 300px; overflow-y: auto;"> <h4 id="intro">Intro</h4> <h4 id="setup">Setup</h4> </div>

Any element with overflow: auto that is not a native scrollable element should be given tabindex="0" so it can be reached by keyboard.

The Big Ideas

Carousel

  1. Four levels are required. Wrapper with an id, .carousel-inner, .carousel-items, and exactly one with .active.
  2. Controls find the carousel by id. If data-bs-target and the wrapper's id do not match, the arrow silently does nothing.
  3. Carousels are a weak accessibility choice. Offscreen slides are hidden from screen readers and keyboard focus. Keep slide content short and non-essential.
  4. Use getOrCreateInstance, not new. The carousel already exists if it has data-bs-ride. Creating a second instance duplicates listeners.

Horizontal Scrollspy

  1. data-bs-spy goes on the scroll container, data-bs-target points at the nav. Two different elements. Do not swap them.
  2. Nested containers need four things. position: relative, a fixed height, overflow-y: auto, and tabindex="0".
  3. Every section needs an id, and every link needs the matching hash. A missing hash or a case mismatch means that link never activates.
  4. A fixed header needs a rootMargin. Otherwise the section title slides under the header and the active state fires too late.

Shared idea

  1. Both components are just markup plus data attributes. The JavaScript reads the attributes and manages the classes. Once you understand which attribute controls what, you can build any variation without touching a single line of JavaScript.
