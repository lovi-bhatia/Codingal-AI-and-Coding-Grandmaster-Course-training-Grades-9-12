Calculator Using JavaScript

A working four-operation calculator with keyboard support and edge-case handling.

Live calculator — click or use the keyboard:
0
0-9 . + - * / Enter Backspace Esc
The entire calculator is four variables 
let current  = "0";    // what is on screen (a string)
let previous = null;   // the number before the operator
let operator = null;   // "+", "-", "*", "/" or null
let waiting  = false;  // if true, the next digit REPLACES current

Every button press either changes current (someone is typing a number) or shifts to a pending operation (someone pressed an operator).

Why current is a string, not a number 
// A number cannot remember these things:
typeof 5     // "number" — cannot tell "5" from "5."
typeof 0.05  // "number" — cannot tell from "0.050"
typeof "0"   // preserved exactly
typeof "5."  // trailing dot is still there

// So we keep the user's typed text as a string
// and only convert to Number when actually calculating.

2. Pressing a Digit — pressNumber

Code: 
function pressNumber(d) {
  // if the previous press left an error, start fresh
  if (current === "Error") reset();

  if (waiting) {
    // user pressed an operator, then a digit
    current = d;
    waiting = false;
  } else {
    // starting from 0 → replace, not append
    if (current === "0") current = d;
    else {
      // 12-digit cap so the display never overflows
      if (current.replace(/\D/g, "").length >= 12) return;
      current += d;
    }
  }
  render();
}
Behaviour to try in the calculator:
  • Press 0 0 0 — the display stays 0 (leading zeros are dropped).
  • Press 5 + 3 — after +, the 3 REPLACES the screen (that is waiting=true).
  • Press 15 digits in a row — the 13th is ignored, so the display never breaks.
  • Press 5 + 0 ÷ 1 = — should show 0, not "Error".

3. Pressing an Operator — pressOperator

Code: 
function pressOperator(op) {
  if (current === "Error") return;

  // Chain: "5 + 3 +" must compute 8 before storing "+"
  if (operator && !waiting) {
    const r = calculate(previous, parseFloat(current), operator);
    if (r === null) return showError();
    current  = String(round(r));
    previous = round(r);
  } else {
    previous = parseFloat(current);
  }

  operator = op;
  waiting  = true;
  render();
}
Two operation modes for operators:
  • Operator swap: 5 + × — replaces the pending operator without computing. (Because waiting is true after the first operator.)
  • Chained compute: 5 + 3 × — computes 8, then becomes 8 ×. (Because a digit was typed, waiting became false.)

That is why one button has two behaviours. It depends entirely on waiting.

4. Equals and the calculate Helper

Code: 
function pressEquals() {
  if (operator === null) return;
  const r = calculate(previous, parseFloat(current), operator);
  if (r === null) return showError();

  current  = String(round(r));
  previous = null;
  operator = null;
  waiting  = true;
  render();
}

function calculate(a, b, op) {
  switch (op) {
    case "+": return a + b;
    case "-": return a - b;
    case "*": return a * b;
    case "/": return b === 0 ? null : a / b;
  }
  return null;
}

// Rounding kills floating point noise
function round(n) {
  return Math.round(n * 1e12) / 1e12;
}
Floating point demonstration: 
0.1 + 0.2          // 0.30000000000000004
round(0.1 + 0.2)   // 0.3

1.1 * 3            // 3.3000000000000003
round(1.1 * 3)     // 3.3

// 1e12 = 1,000,000,000,000
// 12 decimal places is wider than the display
// and narrower than IEEE-754 noise.

Try 0 . 1 + 0 . 2 = — the answer is exactly 0.3, not 0.30000000000000004. That is the whole reason for the round function.

5. Display Formatting — Thousands Separators

Code: 
function render() {
  const valueEl = document.getElementById("calcValue");
  const exprEl  = document.getElementById("calcExpression");

  let shown = current;

  // Do not format "Error", empty, or trailing-dot strings
  if (current !== "Error" && !current.endsWith(".")) {
    const n = Number(current);
    if (!Number.isNaN(n)) {
      shown = n.toLocaleString("en-US", {
        maximumFractionDigits: 10
      });
    }
  }

  valueEl.textContent = shown;
  valueEl.classList.toggle("is-error", current === "Error");

  // Small "5 +" line above the big number
  if (operator && previous !== null) {
    const sym = { "+": "+", "-": "−", "*": "×", "/": "÷" }[operator];
    exprEl.textContent = previous.toLocaleString("en-US") + " " + sym;
  } else {
    exprEl.textContent = "";
  }
}
Formatting examples: 
"1234567"       → "1,234,567"
"1234.5"        → "1,234.5"
"0.0001234"     → "0.0001234"
"5."            → "5."    (don't format trailing dot)
"Error"         → "Error" (red, smaller font)
String(1e21)    → "1e+21" (very large → sci notation)

The trailing-dot check matters — Number("5.") is just 5, so without the check the display would drop the dot the user is still typing.

6. Edge Cases to Handle

The four that bite most calculators: 
// 1. Divide by zero → clear error, block further ops
case "/": return b === 0 ? null : a / b;

// 2. Two decimal points → ignore the second one
if (!current.includes(".")) current += ".";

// 3. Leading zeros → replace, do not append
if (current === "0") current = d;

// 4. Operator, then another operator → swap, do not compute
if (operator && !waiting) { compute(); }
operator = op;
Test each in the calculator:
  • Divide by zero: 5 ÷ 0 = — the display shows Error in red. The next digit starts fresh.
  • Two dots: 3 . . 5 — the second dot is ignored, result 3.5.
  • Leading zeros: 0 0 0 7 — the display shows 7, not 0007.
  • Swap operator: 5 + × 3 = — should be 15, not 15 × 3.

7. Keyboard Support

Code: 
document.addEventListener("keydown", (e) => {
  const k = e.key;

  if (k >= "0" && k <= "9")                handleKey(k);
  else if (k === ".")                       handleKey(".");
  else if ("+-*/".includes(k))              handleKey(k);
  else if (k === "Enter" || k === "=") {
    e.preventDefault();
    handleKey("=");
  }
  else if (k === "Escape")                  handleKey("AC");
  else if (k === "Backspace")               handleKey("DEL");
});
Why the key list is guarded: 
// e.key returns the CHARACTER for printable keys:
"5"  → "5"
"+"  → "+"
Enter → "Enter"
Esc   → "Escape"

// But also your keyboard layout matters:
// shift+"=" on a US layout produces "+"
// "digit5 with shift" produces "%"
// so keep the guard simple and check the
// resulting e.key, not the keycode.

e.preventDefault() is required on Enter — otherwise pressing Enter inside any focused form tries to submit.

8. Button Clicks — One Listener, Not Twenty

Code: 
// Each button carries a data-key attribute:
<button data-key="7">7</button>
<button data-key="+">+</button>
<button data-key="=">=</button>

// ONE listener on the grid handles every button
document.getElementById("calcGrid")
  .addEventListener("click", (e) => {
    const btn = e.target.closest("[data-key]");
    if (!btn) return;
    handleKey(btn.dataset.key);
  });

function handleKey(key) {
  if (/^\d$/.test(key))         pressNumber(key);
  else if (key === ".")         pressDot();
  else if ("+-*/".includes(key)) pressOperator(key);
  else if (key === "=")         pressEquals();
  else if (key === "AC")        reset();
  else if (key === "DEL")       pressBackspace();
  else if (key === "±")         pressSign();
  else if (key === "%")         pressPercent();
}
Why event delegation:
  • One listener instead of twenty.
  • Works if you later add a new button — as long as it has data-key.
  • e.target.closest("[data-key]") handles clicks that land on the button's text or padding.
  • Keyboard and mouse share the same handleKey function — one place to change behaviour.

9. Quick Reference

State at any moment

Variable Holds Example
current The number on screen (as string) "42.5"
previous The stored left operand 10 or null
operator Pending operator "+" or null
waiting Should next digit replace current? true / false

Behaviour summary

Action Effect on state
Press digit while waiting = false Append to current
Press digit while waiting = true Replace current, set waiting = false
Press operator while waiting = false Compute pending, store new operator
Press operator while waiting = true Swap operator only
Press equals Compute, clear operator and previous
Press AC Reset everything to "0"
Press DEL Remove the last character of current
Press ± Toggle leading - on current
Press % current / 100
Divide by zero Show Error, reset on next digit
