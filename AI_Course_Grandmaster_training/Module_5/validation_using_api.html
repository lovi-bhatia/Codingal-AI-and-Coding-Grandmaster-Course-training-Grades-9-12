Form Validation Using a Custom API

Two files: validator.js (the API) and this HTML file. Open this page normally — <script src="validator.js"> loads the module, and every form below is bound in one line: FormValidator.bind(form).

1. Login Form (minimum rules)

Uses HTML5's required and type="email" plus one custom rule (data-rule="password") for minimum password strength.

Validator binding (the only JS this form needs): 
const loginForm = document.getElementById("loginForm");

FormValidator.bind(loginForm);

loginForm.addEventListener("validated", (e) => {
  // e.detail contains every field value
  console.log("would sign in:", e.detail);
});

loginForm.addEventListener("invalid", () => {
  console.log("check the highlighted fields");
});
Live form:
Please enter a valid email.

2. Register Form (custom rules + cross-field match)

Adds minlength, a strong password rule, and data-match="#regPass" so the confirm field must equal the password field.

The two interesting HTML attributes: 
<!-- Password -->
<input name="password"
       type="password"
       required
       data-rule="password"
       data-message="Min 8 characters, letter and digit.">

<!-- Confirm — must equal #regPass -->
<input name="confirm"
       type="password"
       required
       data-match="#regPass"
       data-message="Passwords do not match.">

<!-- No extra JS needed — validator.js handles both -->
Live form:
Please enter 2-40 characters.
Please enter a valid email.

3. Contact Form (optional custom rules)

Optional fields still need rules — the phone rule only runs when the field is non-empty. Optional fields also pass trivially when left blank, which is the correct behaviour.

Optional rules with custom message: 
<input name="phone"
       type="tel"
       data-rule="phone"
       data-message="Phone must be 10 digits (leave blank to skip).">

<textarea name="message"
          required
          minlength="20"
          maxlength="500"
          class="form-control"></textarea>

HTML5's minlength on the textarea is checked on submit — validator.js also re-checks on blur so the user sees the feedback as soon as they leave the field.

Live form:
Please enter your name.
Please enter a valid email.
Please write 20-500 characters.

4. Live API Activity Log

Every event the validator receives is written here in real time. Type, blur, submit — the log shows what the API is actually doing.

Setup that feeds this log: 
["loginForm", "registerForm", "contactForm"]
  .forEach(id => {
    const form = document.getElementById(id);

    // Bind the API
    FormValidator.bind(form);

    // Forward the API events into the log
    form.addEventListener("input", e => {
      if (e.target.matches("input, textarea, select")) {
        log(id, "input", e.target.name);
      }
    }, true);

    form.addEventListener("focusout", e => {
      if (e.target.matches("input, textarea, select")) {
        log(id, "blur", e.target.name);
      }
    }, true);

    form.addEventListener("validated", e =>
      log(id, "validated", JSON.stringify(e.detail)));

    form.addEventListener("invalid", () =>
      log(id, "invalid", "check highlighted fields"));
  });

5. Reference

What the module does on bind

Step What Happens Constraint Validation API call
Adds novalidate Suppresses the browser's own error bubbles —
Attaches blur Validates the field the user just left el.checkValidity()
Attaches input Re-validates only fields already in an error state el.checkValidity()
Attaches submit Calls preventDefault, runs validateForm form.checkValidity()
Dispatches validated Fires when every field passes —
Dispatches invalid Fires when at least one field fails —

Rules bundled in validator.js

Rule Usage Accepts
required data-rule="required" non-empty after trim
email data-rule="email" basic email shape
phone data-rule="phone" 10 digits, whitespace ignored
password data-rule="password" 8+ characters, one letter + one digit
number data-rule="number" parseable Number
min data-rule="min:5" value ≥ arg
max data-rule="max:100" value ≤ arg
minlength data-rule="minlength:3" length ≥ arg
maxlength data-rule="maxlength:40" length ≤ arg

HTML5 attributes still work

Attribute Meaning
required Field must not be empty
type="email" Must look like an email
type="url" Must look like a URL
type="number" Must be numeric
min / max Numeric range
minlength / maxlength Text length
pattern Full regex match

Extending the API

Add a new rule: 
FormValidator.addRule("username", (v) => {
  return v === "" || /^[A-Za-z0-9_]{3,16}$/.test(v);
});

// Now every form on the page can use it:
//   <input data-rule="username"
//          data-message="3-16 letters, digits, underscores">

Rules to remember

Rule Why
Load validator.js BEFORE the inline script Otherwise FormValidator is undefined
Both files in the same folder Otherwise the browser 404s the script
FormValidator.bind(form) per form Each form gets its own listener set
Listen for validated, not submit submit fires whether valid or not; validated only on success
Empty optional fields always pass The rule is skipped, not failed
Client-side validation is UX The server must re-check everything
Clear messages with "" The module clears setCustomValidity("") before every check
